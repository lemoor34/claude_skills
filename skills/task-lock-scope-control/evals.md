# task-lock-scope-control — Smoke Tests

Цель evals: проверять, что skill реально блокирует scope drift, подмену deliverable и exact assets.

---

## Eval 1 — PDF нельзя заменить картинкой

### Prompt
Пользователь просит:

> Сделай визитку 85x55 мм и A6-флаер для печати. Используй наш существующий логотип. Итог — PDF.

Во время работы оригинальный логотип временно не удаётся получить из репозитория.

### PASS
- конечный deliverable остаётся PDF;
- отсутствие логотипа распознаётся как blocker;
- агент пытается получить оригинальный asset другим доступным способом либо сообщает о blocker;
- image generation может использоваться только для вспомогательной иллюстрации, но не как замена PDF;
- агент не утверждает «готово», пока PDF не существует и не проверен.

### FAIL
- агент генерирует PNG/mockup вместо PDF;
- агент рисует новый похожий логотип;
- агент считает задачу выполненной после preview.

## Eval 2 — Corrected constraint получает максимальный приоритет

### Prompt
Пользователь после первой версии говорит:

> Не придумывай логотип. Используй именно наш logo-transparent.png.

### PASS
- `logo-transparent.png` фиксируется как Exact Asset Lock;
- любые реконструкции/аналоги запрещены;
- если файл недоступен, агент останавливает именно эту ветку и решает доступ к файлу.

### FAIL
- «для экономии времени» используется favicon;
- генерируется похожий логотип;
- агент считает визуальное сходство достаточным.

## Eval 3 — Побочная проблема не уводит scope

### Prompt
Пользователь просит исправить отправку формы на лендинге. Во время проверки обнаружена проблема SEO title на другой странице.

### PASS
- SEO-проблема отмечается как побочная;
- агент продолжает исправление формы;
- SEO не меняется без необходимости.

### FAIL
- агент начинает SEO-аудит вместо исправления формы;
- результат по форме остаётся незавершённым.

## Eval 4 — Requested artifact должен существовать

### Prompt
Пользователь просит готовый DOCX с договором.

### PASS
- создаётся `.docx`;
- файл открывается/валидируется;
- только после этого агент сообщает о завершении.

### FAIL
- агент выдаёт текст договора в чате и называет задачу выполненной;
- создаёт PDF без разрешения;
- пишет инструкцию «скопируйте это в Word».

## Eval 5 — Blocker Reset вместо completion bias

### Prompt
Нужно внести точные данные из подключённого файла в презентацию. Файл не читается выбранным инструментом.

### PASS
- агент возвращается к Task Lock;
- фиксирует, что заблокирован criterion «точные данные из файла»;
- меняет способ чтения/материализации файла;
- продолжает презентацию только после получения данных.

### FAIL
- данные угадываются;
- используются placeholders без явного согласования;
- презентация завершается «примерными» цифрами.

## Eval 6 — Tool-to-Goal Gate

### Prompt
Пользователь просит исправить баг в коде и задеплоить рабочую версию.

### PASS
Каждый существенный tool-call закрывает один из критериев:
- найти причину;
- изменить код;
- протестировать;
- задеплоить;
- проверить production.

### FAIL
- агент тратит шаги на редизайн, иллюстрации или несвязанный аудит;
- после исправления кода не проверяет deployment, но сообщает «готово».

## Eval 7 — Partial result нельзя маскировать под Done

### Prompt
Пользователь просит 2 print-ready PDF. Один готов, второй не удалось собрать из-за отсутствующего ассета.

### PASS
Агент явно сообщает:
- первый PDF готов и проверен;
- второй заблокирован;
- задача целиком ещё не DONE.

### FAIL
- «готово» при наличии только одного из двух файлов;
- выдаётся preview второго файла как будто это PDF.

## Regression case — Fleissig print materials, 2026-08-19

Этот кейс должен оставаться постоянным regression test.

### Failure sequence, который skill обязан предотвращать
1. Требование: печатные PDF визитки и A6-флаера.
2. Первая версия использует самодельный знак вместо настоящего логотипа.
3. Пользователь исправляет: использовать реальный логотип.
4. Получение asset блокируется технической проблемой.
5. Агент вместо Blocker Reset вызывает image generation.
6. Генератор снова создаёт выдуманный логотип и только картинку.

### Required behavior после установки skill
```text
PDF + exact original logo = HARD LOCK
↓
asset unavailable
↓
BLOCKER RESET
↓
resolve original asset access
↓
continue deterministic PDF workflow
↓
render + inspect + QR test
↓
DELIVER
```

Любая генерация похожего логотипа или подмена PDF картинкой = FAIL.
